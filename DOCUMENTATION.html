Pipeline:
  • Upload → stored in S3 → FFmpeg transcode (Hangfire worker) → adaptive HLS → CloudFront.
  • Large files use a pre-signed S3 upload (direct PUT, no server round-trip).
  • Playback URLs are signed and only issued to entitled viewers.
API: POST /api/admin/contents → /contents/{id}/video → /contents/{id}/publish

Appendix — Replacing these with real screenshots

  1. Bring the stack up: docker compose up -d sqlserver redis → dotnet run --project OTT.API → seed a tenant, an admin user and a few titles.
  2. Run the app: flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:50664.
  3. Log in, navigate each screen, and capture (browser screenshot / device screenshot).
  4. Drop the images into docs/screens/ and swap the mockups above for <img> tags — or embed them in DOCUMENTATION.md.
Note: on web the video player is limited (media_kit/YouTube/Vimeo are mobile/desktop-oriented), so capture player screens on Android/iOS.
